PR #482
Why PR #482 was raised

Why swap a double for whole pence?

A double can't hold 0.10 exactly. In a payments ledger, that's a bug waiting to happen. Let's store pence as a whole number, like the card schemes do.

1Doubles are binary fractions

0.1 + 0.2 == 0.30000000000000004

Most decimal amounts can't be stored exactly. Each one is very slightly wrong.

2Small errors add up

Sum millions of settlements and totals can drift by pennies. Services round in different places. Finance must explain every penny.

3Whole pence can't round

// before double amount = 268.47; // after long amountMinor = 26847;

Card schemes send amounts in minor units. An integer is exact.

The idea is right. The trouble is how it ships: the table, the event and both services, all in one deploy.

PR #482
PR #482 · Flyway and V3

The migration that closes the door in 5 milliseconds

db/migration/V3__amount_minor_units.sql (lines 1–2 are comments) 3 ALTER TABLE ledger_entries RENAME COLUMN amount TO amount_minor; 4 ALTER TABLE ledger_entries ALTER COLUMN amount_minor TYPE bigint USING (amount_minor * 100)::bigint;

Line 3: rename

From this moment nothing called amount exists. Old ledger code and the reconciliation break.

Line 4: rewrite in place

Every past row becomes pence. Only a script that divides by exactly 100 can bring it back.

In the recorded run, Flyway applied V3 in 0.005 seconds, before ledger-service took its first event. That's the door closing.

What happens when ledger-service starts

1Flyway lists its V…__….sql files
2It reads flyway_schema_history
3It runs what's new, each in a transaction
4Hibernate checks the table matches the code
5Only then does the Kafka listener start

It only goes forward. No undo in the free edition, and none can un-mix events on Kafka.

Expand first. The safe route's V3 just adds amount_minor, nullable.

A v2 event meets v1 code

The v2 event on payments.settled

It reads by field name. No type header (use.type.headers: false), so any JSON maps onto v1's class.

Unknown fields are ignored. Jackson's default. amountMinor is dropped without a word.

A missing double is 0.0. A primitive keeps its default, and BigDecimal.valueOf(0.0) books £0.00.

The skill

One-Way Door: a GitHub Copilot skill for rollback safety

One folder in .github/skills/one-way-door. Copilot loads it when someone reviews a PR, checks a release, changes a migration or an event, or asks “can we roll back?”.

1Two-way or one-way

Classifies every change: safe to roll back, or not.

2When the door closes

For each one-way change: when it closes, what breaks on rollback, and the safe rollback window.

3The blast radius

Other code that reads the same table, column, topic or field, even outside the PR.

4A rollback-safe split

Expand → migrate → contract → drop. It can generate the PRs.

Readers: reconciliation also reports any mismatch.

⇄ Roll back: both columns are there and correct.

The safe route
The safe route · the reader nobody remembered

This time, finance's job moves with the ledger

PR #482 left reconciliation-batch out, and it broke first. The split includes it: two of its four PRs change finance's query, and every rollback test deploys it together with ledger-service.

1 · Expand
No change
SELECT SUM(amount)

The split keeps amount, so the old query still works.

2 · Migrate
Changed: adds a check
SELECT SUM(amount), COUNT(*) FILTER (WHERE amount_minor IS DISTINCT FROM round(amount * 100))

Warns if the two columns disagree, before anyone relies on the new one.

3 · Contract
Changed: switches column
SELECT SUM(amount_minor)

A trigger keeps amount filled, so the old query still works after a rollback.

4 · Drop
No change
SELECT SUM(amount_minor)

Dropping amount is safe only because every reader moved in step 3.

In the rollback test

  • Deploy ledger also deploys reconciliation-batch at the new version. Roll back ledger takes it back too. It reads ledger-service's table, so they move as a pair.
  • It's a batch job: “deploy” means building that version and using it for the next run.
  • After every stage, its total must equal the money sent.
My job ships on my team's schedule. Just tell me when to switch.

Two ordering rules

1Switch to amount_minor any time after step 2.

2Don't ship step 4 until that switch is live.

Why the skill found it

It's in the same repository, so the skill searches it. In another repository it couldn't: a known limitation (TDD section 9).

One click, traced: “Roll back” at 16:58
